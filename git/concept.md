## 깃이 "챙기는 파일" vs "안 챙기는 파일"

두 대(메인컴 + 맥북)로 같은 작업을 할 때 꼭 알아야 하는 개념. 깃은 폴더 안의 **모든 파일을 자동으로 챙기지 않는다.** "이 파일 기록해줘"라고 등록(`add`)한 것만 사진(커밋)에 담기고, 그 사진이 `push`로 깃허브에 올라가 메인컴에서도 보인다.

쉬운 비유: **단체 사진 찍을 때, 프레임 안에 들어온 사람만 사진에 남는 것.** 등록 안 한 파일은 프레임 밖이라 사진에 안 찍히고, 내 컴퓨터에만 남는다.

| 상태 | git status 표시 | 뜻 |
|---|---|---|
| 추적됨(수정) | `M` | 깃이 챙기는 파일이고 내용이 바뀜 |
| 추적됨(새로 추가) | `A` | 방금 `add`해서 다음 커밋에 담길 파일 |
| **안 추적됨** | `??` | 깃이 안 챙기는 파일. 커밋·푸시해도 **안 올라감. 이 컴퓨터에만 있음** |

### 실전 (자서전 책 작업)
- 원본 원고 파일(`docs/`의 .md)은 **추적됨** → `push`하면 메인컴에서도 보이고 검토 사이트에 반영됨
- 작업용 임시 파일(`원고작업/ch2.txt` 같은 워킹본)은 **일부러 안 추적** → 이 맥북에만 두고, 깃허브엔 안 올림
- 그래서 `git add docs/...`처럼 **올릴 파일만 콕 집어서** add하면, 임시 파일이 실수로 올라가는 걸 막을 수 있다

### 기억할 것
- `git status`에서 `??`로 뜨면 "이건 안 올라가는 파일"이라는 신호
- "메인컴에서 안 보여요" = 십중팔구 그 파일이 추적 안 됐거나 push를 안 한 것
- 반대로 비밀번호·개인 메모처럼 **올리면 안 되는 파일**은 `.gitignore`에 적어두면 깃이 영영 안 챙김
