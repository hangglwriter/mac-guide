# 스마트폰 미러링 (scrcpy)

> 안드로이드 폰 화면을 맥북에 띄우고, 맥 마우스·키보드로 조작하기

## 이게 뭔데?

**폰 화면을 맥북 창 하나로 옮겨오는 것.** 강의나 미팅에서 "제 폰에서는 이렇게 나와요"를 보여줄 때, 폰을 카메라로 비추는 대신 맥 화면에 띄워서 같이 보는 방식이다.

폰을 복제하는 게 아니라 **생중계 + 리모컨**에 가깝다. 맥에서 클릭하면 폰이 실제로 눌리고, 폰을 손으로 만져도 맥 화면에 그대로 나온다. 둘 다 동시에 쓸 수 있다.

- 무료, 오픈소스
- 폰에 앱 설치 안 해도 됨
- 계정 로그인 없음
- **안드로이드 전용** (아이폰은 맥 기본 "iPhone 미러링" 사용)

## 설치

```bash
brew install scrcpy
brew install --cask android-platform-tools
```

두 번째 줄의 `adb`는 맥과 폰이 대화하는 **통역기**다. scrcpy 혼자서는 폰에 말을 걸 수 없어서 반드시 같이 필요하다.

설치됐는지 확인:

```bash
scrcpy --version
adb version
```

## 폰 설정 (갤럭시 기준, 최초 1회)

### 1. 개발자 옵션 켜기

```
설정 > 폰 정보 > 소프트웨어 정보 > 빌드번호 (7번 연속 탭)
```

**두 가지 함정이 있다:**

- 갤럭시는 메뉴 이름이 "휴대전화 정보"가 아니라 **"폰 정보"** 다
- 빌드번호는 "폰 정보" 바로 밑에 없고 **"소프트웨어 정보" 안에** 들어 있다. 그 화면은 전부 그냥 글씨만 나와서 누르는 곳처럼 안 보이는데, **그 글씨를 직접 7번 연타**하는 게 맞다

천천히 누르면 카운트가 리셋되니 톡톡톡 빠르게. 3번쯤에서 "개발자가 되기까지 4단계 남았습니다" 토스트가 뜨면 제대로 가는 것이다.

### 2. USB 디버깅 켜기

```
설정 (맨 아래로 스크롤) > 개발자 옵션 > USB 디버깅
```

### 3. 연결 후 허용

USB 케이블로 폰과 맥을 연결하면 폰에 **"USB 디버깅을 허용하시겠습니까?"** 팝업이 뜬다.
→ **"이 컴퓨터에서 항상 허용"** 체크 후 **허용**

> **케이블 주의**: 충전 전용 케이블은 데이터가 안 통해서 폰이 안 잡힌다. 폰 살 때 들어있던 케이블을 쓰자.

### 연결 확인

```bash
adb devices
```

```
List of devices attached
R3CWC0C66RF     device      ← 이렇게 나오면 성공
```

| 표시 | 뜻 | 해결 |
|---|---|---|
| `device` | 정상 | 바로 실행하면 됨 |
| `unauthorized` | 폰에서 허용을 안 누름 | 폰 화면의 허용 팝업 확인 |
| 아무것도 없음 | 케이블/디버깅 문제 | 데이터 케이블인지, USB 디버깅 켜졌는지 확인 |

## 실행

```bash
scrcpy
```

민티에어에는 **클릭 한 번으로 실행되는 앱**도 만들어뒀다. (아래 "앱으로 만들어두기" 참고)

## 단축키

MOD = 왼쪽 `Option(Alt)` 또는 왼쪽 `Command`

| 동작 | 단축키 |
|---|---|
| 홈 | `MOD+h` (마우스 휠 클릭) |
| 뒤로가기 | `MOD+b` (우클릭) |
| 최근 앱 | `MOD+s` |
| 전체화면 | `MOD+f` |
| 검은 여백 제거 | `MOD+w` (여백 더블클릭) |
| 볼륨 | `MOD+↑` / `MOD+↓` |
| 화면 회전 | `MOD+←` / `MOD+→` |
| 폰 화면 끄기 (미러링은 유지) | `MOD+o` |
| 폰 화면 켜기 | `MOD+Shift+o` |
| 알림창 펼치기 | `MOD+n` |
| 맥 클립보드를 폰에 붙여넣기 | `MOD+v` |

마우스 클릭·드래그는 폰 터치처럼 동작한다. 맥에서 파일을 창 안으로 **드래그하면 폰에 복사**되고, APK 파일이면 설치까지 된다.

## 자주 쓰는 옵션

```bash
scrcpy --turn-screen-off     # 폰 화면은 끄고 맥에서만 보기 (배터리 절약)
scrcpy --keyboard=uhid       # 맥 키보드로 한글 입력 (아래 참고)
scrcpy --max-size=1024       # 창 크기 줄이기 (버벅일 때)
```

## 한글 입력이 안 될 때

### 증상

맥 키보드로 폰에 타이핑하면 **마침표나 영문·숫자는 들어가는데 한글만 안 들어간다.**

터미널 로그를 보면 이렇게 찍힌다:

```
[server] WARN: Could not inject char u+c548   ← '안'
[server] WARN: Could not inject char u+b155   ← '녕'
```

### 원인

scrcpy는 기본적으로 **`sdk` 모드**로 동작한다. 안드로이드가 갖고 있는 "키 배열표"에 적힌 문자만 폰에 넣을 수 있는 방식인데, 그 표에는 영문·숫자·기호만 있고 **한글은 없다.**

**비유하면**: 자판기에 버튼이 영문·숫자만 있는 상태다. 없는 버튼(한글)은 아무리 눌러도 안 나온다.

### 해결법 1 - 복사 붙여넣기 (제일 간단)

1. 맥에서 텍스트 복사 (`⌘C`)
2. scrcpy 창을 클릭해서 포커스를 준다
3. `MOD+v` (왼쪽 Command+V 또는 왼쪽 Option+V)

긴 글을 넣을 땐 이게 제일 확실하다. 클립보드를 통째로 옮기는 방식이라 한글도 그대로 들어간다.

### 해결법 2 - uhid 모드 (직접 타이핑)

```bash
scrcpy --keyboard=uhid
```

맥 키보드를 **폰에 꽂은 진짜 외장 키보드처럼** 인식시키는 방식. 키를 눌렀다는 신호만 보내고, 한글 조합은 폰의 삼성 키보드가 알아서 한다. 없는 버튼을 만드는 대신, **한글을 아는 자판기(폰 키보드)에게 일을 넘기는 것.**

**폰에서 최초 1회 설정:**

```bash
# 이 명령어로 설정 화면을 바로 열 수 있다
adb shell am start -a android.settings.HARD_KEYBOARD_SETTINGS
```

또는 scrcpy 창에서 `MOD+k`

- 물리적 키보드 목록에서 레이아웃을 **한국어**로 지정
- **"화면 키보드 표시"** 토글이 있으면 켜두기 (안 켜면 물리 키보드 연결 중엔 폰 화면 키보드가 숨어서, 폰을 손으로 터치해 입력하기 불편해진다)

**맥에서:**

- 맥 입력기를 **영문(ABC)** 으로 바꿔둔다. uhid는 "키를 눌렀다"는 신호 자체를 보내는 방식이라, 맥에서 미리 한글로 조합해버리면 오히려 꼬인다
- 한/영 전환은 scrcpy 창 안에서 `Shift+Space` (안 되면 `Ctrl+Space`)

### 모드 비교

| 모드 | 한글 | 설정 | 언제 쓰나 |
|---|---|---|---|
| `sdk` (기본) | X | 필요 없음 | 영문·숫자만 칠 때 |
| `uhid` | O | 폰에서 1회 설정 | 한글을 직접 타이핑할 때 |
| 복붙 (`MOD+v`) | O | 필요 없음 | 긴 글을 한 번에 넣을 때 |

## 앱으로 만들어두기 (터미널 없이 실행)

매번 터미널을 여는 게 번거로우면 **앱으로 만들어서 스포트라이트(`⌘Space`)로 실행**할 수 있다.

민티에어에는 이미 만들어져 있다:

```
~/Applications/휴대폰미러링 (scrcpy).app
```

`⌘Space` → "휴대폰" 또는 "미러" 만 쳐도 나온다. 실행하면 폰 연결을 먼저 확인하고, 안 되어 있으면 뭐가 문제인지 안내창을 띄운다.

### 만드는 법

AppleScript로 작성한 뒤 `osacompile` 명령으로 앱으로 굽는다.

```bash
osacompile -o ~/Applications/"휴대폰미러링 (scrcpy).app" mirror.applescript
```

소스 백업: `~/Projects/scrcpy-launcher/mirror.applescript`

### 옵션 바꾸는 법

소스 파일에서 이 줄만 고치고 다시 컴파일하면 된다.

```applescript
set opts to ""                      -- 기본
set opts to "--keyboard=uhid"       -- 한글 입력 켜기
```

### 삽질 기록 - 셸 스크립트로 만든 앱은 macOS가 막는다

처음엔 폴더 구조를 손으로 만들고 안에 셸 스크립트를 넣는 방식(`.app/Contents/MacOS/run`)으로 앱을 만들었는데, 실행하면 이 에러가 났다.

```
_LSOpenURLsWithCompletionHandler() failed with error -10669.
```

`-10669`는 **"이 앱을 실행할 권한이 없다"** 는 뜻이다. 애드혹 서명(`codesign`)을 붙여도 똑같았다.

- **원인**: 요즘 macOS는 손으로 조립한 셸 스크립트 앱 번들을 신뢰하지 않는다
- **해결**: `osacompile`로 만들면 macOS가 인정하는 정식 실행파일(`applet`)이 들어간 번들이 나온다

> **교훈**: 맥에서 "클릭하면 명령어가 실행되는 앱"을 만들 땐 폴더를 직접 조립하지 말고 `osacompile`(AppleScript) 이나 Automator를 쓰자.

### 검색에 잘 걸리게 하는 법

스포트라이트는 **파일 이름**으로 찾는다. 그래서 앱 이름에 검색할 만한 단어를 다 넣어두면 좋다.

`휴대폰미러링 (scrcpy).app` 로 지어두면 아래가 전부 검색된다.

| 검색어 | 결과 |
|---|---|
| 휴대폰미러링 | O |
| 휴대폰 미러링 | O |
| 미러링 / 미러 | O |
| 휴대폰 | O |
| scrcpy | O |

이름을 바꾼 직후에 검색이 안 되면 색인을 새로 시키면 된다.

```bash
mdimport ~/Applications/"휴대폰미러링 (scrcpy).app"
```

## 미러링 끄기 & USB 빼기

### 끄는 법

- scrcpy 창을 닫는다 (`⌘W` 또는 창의 빨간 버튼)
- 또는 터미널에서 `Ctrl+C`

### USB는 그냥 빼도 되나? → 된다

**윈도우의 "하드웨어 안전하게 제거"에 해당하는 절차가 맥에서는 필요 없다.**

이유는 **폰이 디스크로 마운트되지 않기 때문**이다. USB 메모리처럼 파일 저장소로 붙어 있으면 "쓰다 만 파일"이 깨질 수 있어서 안전하게 제거가 필요한데, scrcpy 연결은 그게 아니라 **디버깅 통로(adb)** 로만 연결된 상태다. 주고받는 건 화면 영상과 터치 신호뿐이라 빼도 깨질 파일이 없다.

확인해보면 실제로 볼륨 목록에 폰이 없다.

```bash
ls /Volumes/
# Data  Macintosh HD      ← 폰이 없다
```

**비유하면**: USB 메모리는 "짐을 옮기는 중"이라 갑자기 끊으면 짐이 쏟아지지만, 미러링은 "화상통화 중"이라 끊으면 그냥 통화가 끝날 뿐이다.

**다만 순서는 지키는 게 좋다:**

1. scrcpy 창 닫기
2. USB 뽑기

창이 켜진 채로 뽑아도 고장나진 않는다. scrcpy가 "연결 끊김" 에러를 내고 스스로 종료될 뿐이다.

> **예외**: 폰 USB 설정을 **"파일 전송"** 으로 바꿔서 실제로 파일을 복사하는 중이라면 그건 얘기가 다르다. 복사가 끝난 걸 확인하고 빼자. (맥은 기본적으로 안드로이드를 디스크로 못 읽어서, Android File Transfer 같은 앱을 따로 깔았을 때만 해당)

## 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| `adb devices`에 아무것도 없음 | 충전 전용 케이블 | 데이터 케이블로 교체 |
| | USB 디버깅 꺼짐 | 개발자 옵션에서 켜기 |
| `unauthorized` 로 표시 | 폰에서 허용 안 누름 | 폰 팝업에서 "허용" |
| 한글만 입력 안 됨 | `sdk` 모드 한계 | `--keyboard=uhid` 또는 `MOD+v` 복붙 |
| 화면이 버벅임 | 해상도가 큼 | `--max-size=1024` |
| 폰 화면 키보드가 안 뜸 | uhid 모드라 숨겨짐 | 물리적 키보드 설정에서 "화면 키보드 표시" 켜기 |
| 직접 만든 앱이 `-10669` | 셸 스크립트 번들 | `osacompile`로 다시 만들기 |
